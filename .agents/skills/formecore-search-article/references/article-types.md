# Article expression types

Choose one primary type. A secondary device is allowed when it materially
improves the answer, such as a comparison table inside a decision guide.

## Decision comparison

Use when the query contains `比較`, `vs`, `哪個`, price, platform, or fit.

- Lead with a short choice map.
- Compare every option on the same decision factors.
- Give each option a best-fit reader and one decision-changing limitation.
- Prefer multiple use-case winners to a false universal champion.

## Six-axis radar comparison

Use when readers benefit from seeing the shape of each option rather than one
total rank. It works well for games, apps, tools, and products with meaningful
trade-offs.

Define six dimensions for the specific topic. Example app dimensions include:

1. onboarding speed;
2. core task depth;
3. game or companion depth;
4. cross-device use;
5. low-pressure experience;
6. social or collaborative use.

Rules:

- Use a 1–5 scale unless existing project evidence requires another scale.
- State whether scores come from published features, hands-on tests, or both.
- Score every item with the same definitions and evidence date.
- Call scores `editorial fit` or `use-case fit`, not scientific measurements.
- Show the six numeric scores in text next to the chart. The article must remain
  understandable if SVG, canvas, CSS, or JavaScript fails.
- Keep the chart accessible and responsive. Code-native SVG is preferred over
  a raster chart.
- Explain the strongest and weakest dimension in prose beneath each item.
- A summed score may help orientation, but it must not override a reader's
  platform or use-case constraint.
- Do not add decimal precision that the evidence cannot support.

## Ranked roundup

Use when the intent asks for `best`, `top`, `推薦`, or a numbered list and the
ranking criteria can be defended.

- Publish the ranking criteria before the list.
- Separate tested facts from editorial judgement.
- Give update triggers because rankings decay.
- If no single order serves all readers, switch to a decision comparison.

## How-to

Use when the reader wants to complete a task.

- State the result, requirements, and time or effort before the steps.
- Make each step observable.
- Include failure points and recovery, not motivational filler.
- Use product screenshots only when they are current and permitted.

## Explainer

Use for `什麼是`, `為什麼`, mechanism, terminology, or trust questions.

- Answer the definition in the first useful paragraph.
- Use one concrete example before edge cases.
- Separate verified behaviour from analogy or opinion.
- End on the practical consequence, not a generic future-looking paragraph.

## First-person field note

Use only when the writer has real first-party experience, records, screenshots,
or observations. Do not manufacture an experiment or personal anecdote to make
an article sound human. A sourced editorial comparison should stay in an
editorial voice.
